# 安全设计

## 权限边界

- Remote Device Agent 和 MCP 服务由 DSM 套件生命周期脚本以 root 启动，这是用户明确要求的运行模式。
- 文件工具默认只授权套件 workspace；DSM 管理员可以勾选共享目录，设置页只接受 NAS 当前共享目录清单中的路径。
- `allowedDirectories` 始终至少包含 workspace；上游把空数组解释为不限制目录。
- 共享目录白名单只限制依赖 `allowedDirectories` 的文件工具。Shell 工具以 root 执行，仍可访问其他系统路径；不能把目录白名单或上游命令检查描述成 root Shell 沙箱。
- 管理页写设置前通过 Synology `authenticate.cgi` 验证 DSM 会话及 administrators 组身份，并校验 POST 来源；授权状态接口不写配置。
- 自启动开关只控制 DSM 开机阶段自动启动，不阻止管理员在套件中心手动启动。代理进程异常退出时 supervisor 按递增间隔重启，最长等待 60 秒；日志超过 10 MiB 时轮转一份。

## 网络与授权

- NAS 不监听公网 MCP 管理端口；远程工具调用由官方设备代理主动连接 Desktop Commander Remote。
- 设备码、验证链接和到期时间只显示上游真实返回值；本地 UI 不生成模拟授权状态。
- 授权状态页通过 DSM 第三方 CGI 集成。页面验证目标必须是 HTTPS 的 `desktopcommander.app` 官方域名后才自动打开；更改设置的 CGI 会校验 DSM 管理员会话。
- 授权状态文件仅授予 root 和 DSM HTTP 服务组读取权限；访问令牌、刷新令牌和设备密钥仍留在 root 专用目录中。
- 授权凭据位于 DSM 持久变量目录，权限限制为套件用户可读；不得写入仓库或普通日志。
- 上游遥测默认关闭。设备代理的数据流经过 Desktop Commander 官方 Remote MCP 服务，安装说明必须披露这一点。
- 管理页面应通过 DSM 套件入口打开，并避免新建额外的公网端口或修改 NAS 网络设置。

## 日志

- 服务日志限制大小并轮转；界面仅显示经过脱敏的内容。
- 命令行参数、授权码、访问令牌、刷新令牌及文件内容不得出现在普通服务日志中。
- Desktop Commander 本地工具历史可能包含调用参数。正式版必须核查并实现符合上项的脱敏策略后，才可启用对应历史工具。
