# 开发与验收记录

## 1.0.0-0012 候选改动（2026-11-27）

- 套件服务与 Remote Device Agent 改为 root 运行。
- DSM 管理页增加共享目录勾选和开机自启动设置；目录列表由 NAS 的 `synoshare` 共享配置读取，设置 CGI 要求 DSM 管理员会话。
- Desktop Commander 文件工具默认只保留套件 workspace，空白目录列表不会被解释为无限制访问。root Shell 仍能访问系统路径。
- 增加 supervisor：代理进程退出后按 2 秒起步、最高 60 秒的退避间隔重启；稳定运行 5 分钟后重置等待间隔；服务日志达到 10 MiB 时轮转一份。
- SPK 根目录加入上游官方 Desktop Commander 标识的 72px 与 256px 图标。
- 本地 SPK 结构与脚本语法检查通过；NAS 实机覆盖升级、root 下的工具行为、共享目录设置、开机自启和断线恢复仍待 DS3615xs-j 实测。

## 1.0.0-0013 环境修复（2026-11-27）

- 清除 DSM 传入的 `LD_PRELOAD` 与 `LD_LIBRARY_PATH`，避免 musl Node 加载 glibc hook 库。
- 检查脚本要求验证打包后的 Node 启动器包含该环境清理。
- 该修复已在目标 NAS 的 0013 安装中得到初步实测，细项见下节。

## 1.0.0-0014 管理页修复（2026-11-27）

- 加载共享目录设置时先读取 DSM `SynoToken`，并在设置 CGI 的 GET 查询中传递，满足 DSM 6 的 CSRF 会话校验。
- 修正 DSM 6.2 `synogroup --get administrators` 的成员解析：用户条目位于 `Group Members:` 后续行，而不是标题行。
- 设置写入继续要求已登录的 DSM 管理员，并保留同源校验；实际页面保存结果待 NAS 管理员页面复验。

## 已核实的上游事实

- `wonderwhy-er/DesktopCommanderMCP` 是 MIT License 项目；其本地 MCP 服务提供文件系统、进程及命令工具。
- 上游包当前要求 Node.js `>=22.12.0`。CI 已在 Node.js 24.22.3 环境完成 `npm ci` 的 TypeScript 构建步骤。
- 上游提供 `remote` 设备代理；它请求设备码、展示官方验证 URL 和有效期、轮询授权，并把本地 MCP 工具接入 Desktop Commander Remote。
- 该代理固定信任 `desktopcommander.app` 的官方域名及指定 Supabase 项目；远程 MCP 服务端本身不在上游开源仓库中。因此本套件只调用官方服务，不声称服务端已自托管。
- ChatGPT 的官方自定义 MCP 连接要求远程 MCP 入口或受支持的 Secure MCP Tunnel；账户套餐与工作区策略会限制可用操作。NAS 局域网地址本身不是公网 HTTPS MCP 端点。
- 本项目通过上游真实设备授权和工具调用验收连接。没有完成授权前，管理界面必须显示“未授权”。
